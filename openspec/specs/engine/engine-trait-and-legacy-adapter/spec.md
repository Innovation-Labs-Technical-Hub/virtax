# Engine trait & legacy adapter Specification

## Purpose
Common Engine trait; LegacyEngine calls VBoxCAPI on a dedicated pool, codegen from XIDL; keeps VBoxSVC resident. Module `EN-01` (Engine trait & legacy adapter; Vietnamese: "Engine trait & Legacy adapter") from BRD-10, phase P1, priority Must. Owner crates: virtax-engine, vbox-sys, vbox-adapter. Depends on: none. VirtualBox reference: `src/VBox/Main/cbinding (VBoxCAPI), Main/glue, Main/idl`. Implementation status (2026-11-24): partial — `Engine` trait, `MockEngine` and `VirtaxVmmEngine`; the VirtualBox legacy adapter (VBoxCAPI) is not started.

## Requirements

### Requirement: Engine trait as the strangler seam (FR-EN01-001)
Virtax SHALL provide "Engine trait as the strangler seam" as specified by FR-EN01-001 (BRD-10, priority Must, phase P1; Vietnamese: "Trait Engine là đường nối strangler").

#### Scenario: Specified behaviour of FR-EN01-001
- **WHEN** the behaviour FR-EN01-001 covers is exercised
- **THEN** it behaves as BRD-10 specifies: The `virtax-engine` crate defines the async `Engine` trait (create, apply → ApplyMode, start/stop/snapshot with an `OpHandle`, open_display, events, metrics, per-host `EngineCaps`). `virtaxd` reaches engines only through it; every engine runs one shared contract suite.
- **AND** the VirtualBox reference for the current behaviour is `new (vi-03 §C4 L4); Frontends/VBoxBFE/VBoxBFE.cpp:712-850`

#### Scenario: Acceptance for FR-EN01-001
- **WHEN** the FR-EN01-001 acceptance check is run
- **THEN** A ≥ 60-case contract suite passes on LegacyEngine (P1) and VirtaxVmmEngine (P2); CI rejects `vbox_adapter` imports outside the engine crate.

### Requirement: FFI on dedicated threads, right apartment, deadlines (FR-EN01-004)
Virtax SHALL provide "FFI on dedicated threads, right apartment, deadlines" as specified by FR-EN01-004 (BRD-10, priority Must, phase P1; Vietnamese: "FFI trên thread riêng, đúng apartment, có deadline").

#### Scenario: Specified behaviour of FR-EN01-004
- **WHEN** the behaviour FR-EN01-004 covers is exercised
- **THEN** it behaves as BRD-10 specifies: CAPI calls run only on a dedicated pool. - **AND** the VirtualBox reference for the current behaviour is `VBoxCAPI.cpp:406-470; glue/initterm.cpp:628-635`

- **THEN** Given a VM process under SIGSTOP, Then calls to other VMs keep p95 ≤ 5 ms and calls to the hung VM return VTX-ENG-004 within 10 s; the UI thread is never held > 50 ms.

### Requirement: As built — Apply-mode table for engines without live reconfiguration
The MockEngine and `VirtaxVmmEngine` SHALL report every change as Live on a stopped machine; on a running machine, name, groups, tags, OS type and integration SHALL be Live, display and boot settings NextBoot, and everything else NeedsPowerOff. Source: `crates/virtax-engine/src/lib.rs` (`apply_mode_for`).

- **WHEN** a dry-run update of memory is made on a running machine
- **THEN** the field reports NeedsPowerOff
- **AND** this is verified by `apps/virtaxd/src/daemon.rs::update_requires_power_off_for_memory_while_running`
